# Secrets Management Strategy

This document outlines the repository's secrets management policy, handling rules, and defense-in-depth safeguards.

## Policy Overview

Secrets (`*.tfvars`, `.env`, `/srv/admin/secrets/*`, and `ansible/**/secrets.yml`) are stored **in plaintext** on the server or workstation for operational simplicity and are **strictly forbidden from being committed to Git**.

This repository is publicly hosted, so operational identifiers, tokens, and credentials must never appear in version control.

## Defensive Safeguards

Protection is enforced by multiple defensive layers:

- **Git Exclusion**: `.gitignore` strictly blocks `.env`, `*.tfvars`, `*.tfstate`, `secrets.yml`, `secrets/` (`/srv/admin/secrets/`), and private keys (`id_ansible`, `id_admin`). Only `.example` templates are tracked.
- **Git Pre-commit Hook**: Automatically scans staged files and diff content before any commit can be created, catching hardcoded secrets, private keys, and unauthorized files.
- **CI/CD Pipelines**: Automated GitHub Actions and GitLab CI workflows fail immediately if any secrets or sensitive file patterns are detected in pull requests or pushed commits.
- **Security Assessment**: Detailed risk analysis and organizational threat modeling are documented in [Potential Security Issues](potential_security_issues.md).

## Secret Types & Handling

| Secret Type | Local File (Gitignored) | Tracked Template / Handling |
| :--- | :--- | :--- |
| **Private Operational Data** | `PRIVATE.md` | Machine-specific identifiers, node names, and local IPs (documented in `AGENTS.md`) |
| **Proxmox API Credentials** | `opentofu/terraform.tfvars`, `.env` | `opentofu/terraform.tfvars.example`, `.env.example` |
| **Ansible Inventory** | `ansible/inventory/hosts.ini` | Pre-configured with `localhost` & internal SDN IPs (tracked) |
| **Host Secrets & Passwords** | `/srv/admin/secrets/*` | Auto-generated by Ansible bootstrap on Proxmox host |
| **Atlantis Proxmox VE Token** | `/srv/admin/secrets/atlantis_proxmox_token` | Scoped strictly to `/pool/dev-app` and `/pool/prod-app` (see [Permissions](../conventions/permissions.md)) |
| **Ansible Secret Overrides** | `ansible/group_vars/all/secrets.yml` | `ansible/group_vars/all/secrets.yml.example` (optional overrides) |
| **SSH Private Keys** | `secrets/id_ansible`, `secrets/id_admin` | Auto-generated in `/srv/admin/secrets/` (gitignored) |

## Ephemeral In-RAM Secrets Injection

<!-- [oman->req~in-ram-container-secrets~1] -->
Application container secrets retrieved from the centralized secrets manager during deployment pipelines are injected directly into RAM-backed tmpfs (`/dev/shm/<app>/<secret>`, mode `0400`) and mounted via Docker Compose file secrets (`/run/secrets/<secret>`). Unencrypted application secrets are never committed or written to persistent VM disks.
